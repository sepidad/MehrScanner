# MehrdadScaner

MehrdadScaner is a small learning project for carefully testing a small number of candidate IPs for a VLESS-over-TLS profile.

It is written from scratch and intentionally keeps the first version easy to understand. It does not copy the other scanner.

## What it checks

For each candidate IP and port, it performs three checks:

1. TCP connect: can your computer open a socket to `IP:port`?
2. TLS handshake: does the candidate accept TLS when we send your original `sni`?
3. WebSocket upgrade: if your config uses `type=ws`, does the candidate answer the WebSocket upgrade request for your original `host` and `path`?

This does not prove the full VLESS tunnel works. It is a conservative pre-filter that finds candidates worth testing with a real client or xray-core.

## Windows app

Double-click `Start_MehrdadScaner.vbs`. It opens the graphical application without requiring PowerShell or CMD. If Windows does not recognize the Python launcher, use `Start_MehrdadScaner.bat` once to see the error message.

The app lets you paste a VLESS URL, select candidate count and concurrency with the mouse, start or stop scanning, and see validated Stage 2 IPs in a table. By default, Stage 1 finishes first and Stage 2 validates the best-ranked candidates. The optional fast mode starts Xray on early clean candidates while Stage 1 continues, which is faster but does not guarantee those are the final best candidates.

Stage 2 can measure latency, download, and upload through each selected candidate. The command line defaults to 10 MB download and 10 MB upload per validated IP (`--download-bytes` / `--upload-bytes`); the GUI defaults to 0 (skip) so validation is quick. Change the MB fields to match the amount of traffic you are comfortable using. Results are stored in `out\\xray_validated.csv` with latency, download Mbps, upload Mbps, and byte counts.

Use the app's "Reset Results" button before a fresh search. It deletes only files generated by the scanner in the configured output folder, including saved clean candidates, live hits, generated configs, and previous Xray validation results.

The app has separate "Stop Stage 1" and "Stop Stage 2" buttons. Stopping Stage 1 keeps clean IPs already found and then can continue with normal Stage 2 validation. Stopping Stage 2 preserves completed validation results and prevents new transfer tests from starting.

## Command line

Run one fast local batch using the port from your config:

```powershell
python .\mehrdadscaner.py --config "vless://YOUR-UUID@example.com:2083?encryption=none&security=tls&sni=example.com&fp=chrome&insecure=0&allowInsecure=0&type=ws&host=example.com&path=%2Fyour-path#example"
```

By default, Stage 1 runs one small batch: about 300 random candidates from the Cloudflare ranges (20 per range), concurrency 64, and no artificial delay. It stops after the first batch unless `--continuous` or `--stop-after-hits` is given.

Avoid running large batches through a VPN/proxy/TUN route. If you are not sure whether traffic may exit through a server, use the egress check below.

If you want the scanner to ask for each setting step by step and accept Enter as the default, run it without `--config` or pass `--interactive`:

```powershell
python .\mehrdadscaner.py --interactive
```

For extra protection, make the scanner check the current public egress IP before it starts. You can provide your own blocked VPN/server exit addresses:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --require-direct-egress --blocked-egress-ips "YOUR_BLOCKED_EXIT_IP"
```

For a stricter check, first learn your normal home/ISP public IP, then require that exact IP:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --require-direct-egress --expected-egress-ip "YOUR_HOME_PUBLIC_IP"
```

If you want the slow protective mode, use:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --safe
```

Continuous mode is available only as an explicit opt-in. Stop it with `Ctrl+C`:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --continuous
```

Or let it keep sampling batches until it finds enough hits, then stop automatically:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --stop-after-hits 150
```

When a clean IP is found, the scanner can probe neighboring `/24` blocks around it on the next pass. The default interactive flow asks about this and reuses the clean IPs from the previous run automatically.

Run a scan against common Cloudflare TLS ports:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --ports common
```

Run a scan against common Cloudflare non-TLS HTTP ports:

```powershell
python .\mehrdadscaner.py --config "YOUR_NON_TLS_VLESS_URL" --ports http
```

Choose modest manual parallelism between 1 and 8:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --concurrency 2
```

Control pacing between connection attempts:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --delay 2 --jitter 1
```

Run against your own candidate list:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --candidates .\candidates.example.txt
```

## Output files

After a run, the `out` folder contains:

- `results.json`: full machine-readable results
- `results.csv`: spreadsheet-friendly results
- `clean_candidates.txt`: clean IPs only, sorted fastest to slowest
- `vless_top_configs.txt`: top generated VLESS configs with the fastest IPs inserted
- `hits.csv`: live hit log, written immediately while scanning
- `hits.jsonl`: live machine-readable hit log, written immediately while scanning

By default, failed candidates are not printed. Use `--show-failures` if you are debugging.
When a run finishes, the scanner prints the best results found in PowerShell and rewrites `clean_candidates.txt` in fastest-to-slowest order.

By default, it generates up to 10 ready-to-use VLESS links. Change that number with:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --config-count 20
```

Use a custom generated-config remark:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --config-remark "WS-afterwar-2083 100 GB"
```

## Stage 2: xray-core validation

Stage 1 finds promising IPs. Stage 2 uses real xray-core validation on the best Stage 1 hits and can measure download and upload through each candidate.

Run Stage 1, then validate the fastest hits with xray-core:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --xray
```

For Stage 2 validation, keep xray concurrency low:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --xray --xray-concurrency 1
```

Measure 5 MB download and 5 MB upload for each Stage 2 candidate:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --xray --stage2-count 30 --download-bytes 5000000 --upload-bytes 5000000
```

XHTTP configs are supported. Stage 1 uses TCP+TLS as the pre-filter for `type=xhttp`, then Stage 2 uses xray-core for the real tunnel test.

For `type=ws`, a candidate is only treated as clean when TCP, TLS, and WebSocket all succeed. For `type=xhttp`, TCP and TLS are enough for phase 1 before xray validation.

The scanner prints running counts while it works, including how many endpoints it has scanned so far and how many clean hits it has found.

If `xray.exe` is not found, the scanner downloads the official Windows 64-bit Xray-core release into:

```text
<this project folder>\tools\xray
```

It does not modify your global Windows PATH.

Control how many Stage 1 hits get real xray testing:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --xray --stage2-count 50
```

Stage 2 outputs:

- `xray_validated_ips.txt`
- `xray_validated.csv`: validation state, latency, download Mbps, upload Mbps, and transferred bytes
- `xray_validated.json`
- `vless_xray_validated_configs.txt`

## How the best IPs are chosen

A single handshake measurement is noisy: one lucky fast (or unlucky slow) run
can misrank an IP. Two mechanisms make the ranking more robust:

1. **Stage 1 re-measurement pass (recheck).** When a normal (non-streaming)
   Stage 2 run is about to pick candidates, the top 120 Stage 1 hits are
   re-probed 3 times each. Each candidate is ranked by the best clean latency
   it produced, and candidates that stop passing the phase-1 clean test on the
   majority of probes are pushed to the end so they do not shadow fast,
   reliable IPs. Control it with `--recheck`, `--no-recheck`,
   `--recheck-top`, `--recheck-repeats`, and `--recheck-concurrency`.

2. **Weighted composite Stage 2 ranking.** Validated candidates are ordered by
   a single rank that combines latency, download and upload (rank-based, so a
   missing measurement or an outlier cannot distort the order). The default
   weights are 0.5 latency / 0.3 download / 0.2 upload; tune them with
   `--rank-weight-latency`, `--rank-weight-download`, and
   `--rank-weight-upload`. This same ordering is used for `xray_validated.csv`,
   `xray_validated_ips.txt`, `vless_xray_validated_configs.txt`, and the GUI's
   "Select Top 20 Best", so the files and the app always agree.

## V2rayN (or other VPN) compatibility

By default the scanner bypasses the Windows system proxy, so it can fetch Cloudflare
ranges, detect your real egress IP, and test candidates with **pure internet** even
while V2rayN is running in system-proxy mode. Uncheck "Use system proxy"
(Advanced Settings > Scan tab) is the default.

### TUN mode

TUN mode routes **all** traffic at the network layer, so a system-proxy bypass is not
enough. The scanner detects TUN adapters and, by default (GUI checkbox "Refuse to scan
if TUN/VPN routing is active"), refuses to run when it finds one. This protects you from
accidentally scanning through the VPN.

To explicitly allow the scanner with TUN active, add an exclusion rule so this app
bypasses TUN:

1. Open V2rayN > Settings > Routing (or "Routing settings" / "TUN settings" depending on version).
2. Add an **Exclude process** (or routing rule with `outboundTag: direct`) entry for:
   - `python.exe`
   - `pythonw.exe`
   - `xray.exe` (used by Stage 2)
3. Then either uncheck the GUI "Refuse to scan if TUN is active" option, or pass `--allow-tun`.

You can also test the guard from the command line:

```powershell
python .\mehrdadscaner.py --config "YOUR_VLESS_URL" --check-tun
```

With `--check-tun`, the scanner exits with code 2 and a warning if a TUN adapter is active.

## Cloudflare ports

Cloudflare supports different proxy ports:

- TLS/HTTPS-style ports: `443`, `8443`, `2053`, `2083`, `2087`, `2096`
- Plain HTTP/non-TLS ports: `80`, `8080`, `8880`, `2052`, `2082`, `2086`, `2095`

If your VLESS config says `security=tls`, usually scan the exact port from your config first. For your example, that is `2083`.

Use `--ports common` only when you intentionally want to try the common TLS ports. Use `--ports http` only for non-TLS configs.

## Important notes

Only test networks and services you are allowed to test. Keep limits modest. Do not run large candidate lists through VPN, proxy, or TUN routes, because the exit server can be reported as the source of scan-like traffic.

Cloudflare official IPv4 ranges are fetched from:

https://www.cloudflare.com/ips-v4
